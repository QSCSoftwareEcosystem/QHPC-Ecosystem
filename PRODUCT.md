# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Program managers assessing the QSC software ecosystem, followed by scientific
software developers and researchers composing and running governed workflows.
Program managers need a clear first view of credible scientific journeys;
developers can move into capability-level composition once the value and
execution boundary are understood.

## Product Purpose

EQO-QSC presents and governs quantum-classical software workflows. It connects
published operations through typed artifacts, records provenance, and makes
runtime readiness and scientific limitations inspectable.

## Positioning

EQO-QSC is an orchestration control plane: it does not replace project tools
with notebook-side calls. It exposes bounded, admitted tool operations and
their typed handoffs as governed workflows.

## Operating Context

Users work in the EQO Workbench with published workflow templates, capability
records, run and artifact records, local development workers, and selectively
admitted container or wheel runtimes. The Composer has a guided scientific
showcase mode and an advanced workflow graph mode.

## Capabilities and Constraints

The guided Composer should lead with scientific showcases for program-manager
presentations. Capability-level discovery and composition remain an advanced
path. A workflow is not presented as ready merely because it is published:
required runtime availability and explicit development, hardware, and
license-related boundaries must remain visible.

## Brand Commitments

Preserve the existing EQO-QSC Workbench identity and its evidence-led,
precise voice. Do not overstate development simulations, optional runtimes, or
hardware readiness.

## Evidence on Hand

Published workflow definitions, capability registry records, worker state, run
records, artifacts, validation evidence, and the Workbench interface provide
the available proof. No benchmark or facility-HPC claims may be fabricated.

## Product Principles

- Lead with inspectable scientific value.
- Keep every artifact handoff and execution boundary explicit.
- Separate published, ready, gated, and blueprint states.
- Make advanced composition available without obscuring the first journey.

## Accessibility & Inclusion

Preserve responsive, keyboard-accessible Workbench behavior and reduced-motion
support.
